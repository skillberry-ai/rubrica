The Rubrica Run
the stages, the gates, and the artifacts between them

Rubrica builds an agent test suite for a target system out of the artifacts that describe it — specs, captured trajectories, source — by chaining AI skills over a schema-validated on-disk contract. The experiment it runs is falsifiable: does prompt-carried judgment survive a chain of artifact handoffs well enough to produce a suite worth running? Everything below is the apparatus that makes the answer readable.

The run, end to end

Read top to bottom. Each row is one stage: what dispatches it, the artifact it leaves in the run directory, and the deterministic gates that must pass before the next stage is dispatched at all. The magenta bands are where the run stops for a human.

Artifacts on disk are the only channel

This is the one architectural rule, and the reason the experiment can be read at all. A stage is dispatched with exactly three things — the run directory, the stage name, and its skill file path. If a stage needs a fact, it reads it from an artifact, or it does not have it.

The cost of that rule is real: no stage can lean on a fact it was not handed a file for. The payoff is that every handoff is inspectable after the fact. When a suite comes out wrong, the artifact that carried the mistake is on disk with a name, and the stage that wrote it is the one to blame — which is what makes a bad run evidence instead of an anecdote.

Before you raise a finding against a stage

Check what the stage's reads actually gives it. A finding that requires knowledge outside the contract is a finding against the contract or the fixture, never against the prompt.

Two check layers, and what neither of them checks

Layer 1 · rubrica validate

JSON Schema, one schema per artifact kind, shipped as package data. validate.STAGE_ARTIFACTS says which kinds a stage must have produced, so a stage that wrote nothing fails rather than passing trivially.

Layer 2 · rubrica check-refs

Cross-artifact references, seed conformance, reachability, invariant evaluation. It runs every checker the run currently has inputs for — there is no such thing as a stage-scoped check-refs.

Layer 2 checks that an element references a resolvable claim. It never checks that the claim supports it. Support is semantic, and no mechanical check for it exists here on purpose — two real defects once lived under that hole in the golden fixture itself. What no check reaches at all is whether a dispatched model actually followed its prompt; that is what the live exercises are for, and one recorded dispatch is one sample.

The exit-code contract

The orchestrator has no judgment of its own about whether a stage went well. It branches on three integers, and the whole repair policy follows from them.

Fan-outs, and why the barrier is not decoration

Four stages fan out: extract per admitted input, propose per batch, instantiate per active scenario, challenge per instance. Members are concurrent and mutually blind. The gate that follows is not.

propose became a fan-out by taking the shared document off both sides of its contract. It used to declare scenarios under reads and writes both, and that is what made concurrency impossible: two members appending to one 02-scenarios.json would each read the same file and overwrite the other's scenarios, with no gate anywhere able to report the loss. Now each member writes 02-scenarios/round-N/<batch>.json and only that, and propose-seal assembles the list in code — which is also what bounds one member's output, because a round no longer has to re-emit every earlier round to keep the document whole.

The human gates

Gates 1 through 3 review a judgment made from evidence already in the run; a human overturning one corrects an inference about the target. Gate 0 decides what the run can ever know — which makes it different in kind, and is why the triage family cannot also hold it. The same party selecting the inputs and ratifying the selection would make the whole run unfalsifiable.

--no-gate

The only way to skip a human gate, and it substitutes an assumption — that the human would have approved — for the gate's entire content. Recording that it was passed is what keeps the reproducibility claim honest; claiming to have gated while skipping is worse than not gating.

What is on the plate but is not a stage

rb-orchestrate

A skill that declares no stage and no schemas. It dispatches extract through emit, holds gates 1–3, and writes decisions.md. It never runs survey, never dispatches any pass of the triage family, and never holds gate 0 — all three are finished before it is dispatched at all.

The code stages

survey, triage-slices, triage-seal, intake and smoke run as code, so they have no skill file and no manifest.stages entry. Their absence there is not a finding.

The measurement tools

compare-gold and sample-for-review write under measurement/, deliberately outside the numbered prefixes: those are the stage contract, and no orchestrator dispatches a tool. diff-runs and claim-utilisation write nothing at all — they print.

The reports that are not gates

claim-utilisation and gate-brief always exit clean on a readable run. gate-brief composes what already exists into the reading surface at each human gate — it does not decide anything.
